# 动效性能检测与用户强制开启设计

日期：2026-11-16
状态：按用户提出的“自动判断性能，并允许强行打开”需求实施；自动执行模式采用推荐方案。

## 目标与范围

新安装默认使用自动模式。程序在创建 Three.js 剑境前检测图形能力，在运行时用实际渲染帧率校正档位。用户可以选择自动、强制开启、轻量或关闭，选择保存在本机。开关覆盖首页 3D、边框飞剑和界面 CSS 动效，不修改剑阵、主剑模型、终端或连接逻辑。

## 方案比较

1. **能力检测与帧率反馈（采用）**：一次性 WebGL2／CPU／设备内存／软件渲染器检测，再依据持续低帧率逐级降级。无需额外跑分，能反映真实场景；无法识别的硬件按未知处理，不凭空判弱。
2. 仅检查硬件参数：实现简单，但核心数和显存不能直接代表 Three.js 帧率，容易误判。
3. 启动时执行高负载 GPU 跑分：可比性较好，但额外消耗电量并拖延开屏，违反动效不得延迟业务操作的现有约束。

## 设置和判定

`MotionPreference` 为 `auto | full | light | off`；`MotionTier` 仍为实际生效的 `full | light | off`。沿用 `orbit:motion-tier` 保存显式用户选择，缺失值代表自动，旧版完整／轻量／关闭设置无损迁移。

自动模式：

- WebGL2 不可用或检测到 SwiftShader、llvmpipe、softpipe、Software、Microsoft Basic Render 等软件渲染器：关闭。
- 已知逻辑处理器不超过 2 个，或已知设备内存不超过 2 GiB：关闭。
- 已知逻辑处理器不超过 4 个，或已知设备内存不超过 4 GiB：轻量。
- 系统 `prefers-reduced-motion: reduce`：自动模式关闭。
- 其他情况先启用完整；未提供的内存等参数不惩罚设备，缺少调试显卡扩展时不把未知显卡误报为软件渲染。

在首页欢迎剑境记录实际渲染帧率，每约 3 秒汇总一次。完整档连续两个样本低于 42 fps 降为轻量，轻量档连续两个样本低于 24 fps 关闭。切页、暂停、组件 inactive、页面隐藏时不采样；一次偶发卡顿不降级。自动关闭后保持静态，不来回跳动；设置页的“重新检测”按钮可原地重新评估，不需要离开自动档或刷新应用。帧率监测不控制手动强制完整、手动轻量或关闭。

强制开启始终选择完整，不被硬件、运行时帧率或系统减少动态效果覆盖。设置页明确提示可能卡顿、增加资源占用。它不能使不支持 WebGL2 的设备具备图形能力；真正初始化失败时继续沿用静态剑图、错误提示和手动重试。

## 组件和数据流

新增 `services/motion-performance.ts`，提供无副作用档位解析、能力输入评估、软件显卡识别与持续低帧率判定。浏览器图形探测单独封装并主动释放临时 WebGL 上下文，清理异常不覆盖探测结果，不把显卡识别信息写入本地存储或日志。

`stores/workbench.ts` 保存用户偏好、实际档位和检测状态，统一应用 `data-motion`、`data-motion-preference`、`data-motion-generation` 和供首页提示使用的 `data-motion-reason`。自动检测在读取本机设置后、加载 Three.js 场景前执行，不增加人为启动等待。系统减少动态效果监听统一由 store 管理；设置更改增加采样代次并重置旧帧率样本，高对比度或主题更改不意外撤销运行时降级。根属性只在实际值变化时写入，FPS 更新不重写主题、不触发同档位场景更新或强制 resize。

`OrbitStage3D.vue` 在根节点偏好尚未初始化时保持关闭，不启动 Three.js 导入；偏好就绪后读取实际档位并报告测量帧率，不各自创建探测 WebGL 上下文。采样代次变化时从下一真实渲染帧重新计时，不混入手动档或旧检测周期的样本。关闭时停止 RAF，并释放几何、材质、纹理和 renderer；保留 canvas 以便重新开启。异步加载和上下文丢失时保持已有 disposed、contextLost 保护。

`SettingsPage.vue` 使用“自动（推荐）／强制开启／轻量／关闭”选择器，显示实际档位、判断原因及最近帧率；自动模式提供显式“重新检测”按钮。CSS 减少动态效果规则只在未明确强制开启时生效。

## 错误处理

能力探测抛错、上下文返回 null 与低性能渲染均不阻断主机、终端和设置操作。存储不可用时保留本次会话选择。图形上下文恢复和强制开启沿用已有重建流程；没有 WebGL2 时不承诺能显示 3D。检测只提供当前设备的启发式建议，不宣称绝对性能认证。

## 验证

- 单元测试：强／中／弱硬件、未知参数、WebGL2 缺失、软件渲染、系统减少动态效果、强制覆盖、持久化值解析、未初始化档位默认关闭、探测清理异常、连续低帧率及偶发低帧率。
- 桌面端到端：模拟低性能与软件 GPU 的自动关闭、强制开启后的完整剑阵、系统减少动态效果下的强制覆盖、关闭后 WebGL 绘制停止与资源释放、刷新后偏好保持、原地重新检测、同档位采样代次重置，以及健康采样期间 canvas 尺寸不被重写。上下文恢复后、点击控制按钮前，比较连续真实渲染像素。
- 实际启动：确认本机自动模式能显示完整剑阵，并读取设置页截图。
- 回归：类型检查、格式、全部单测、构建和相关桌面用例；轩辕剑与现有用户未提交改动必须保留。

## 实施假设

- 保留现有“轻量”选项，自动模式是三档档位的决策者，不另造一套场景质量。
- 用户要求的强行打开明确包含覆盖系统减少动态效果；设置页同步给出提示。
- 当前请求未要求提交或重新打包，因此不自动提交、不覆盖既有安装器。本次只记录源代码设计与实现验证。
