# 开发阶段与验收计划

版本：v1.0 · 日期：2026-11-14。以下为目标开发任务及验收条件；目前已进入 M0/M1，已执行的软件测试见[开发记录](07-IMPLEMENTATION-STATUS.md)。文档完成不代表应用开发完成。

## 1. 开发顺序与依赖

### M0 技术验证与版本锁定

交付：最小终端验证工程、依赖/许可证清单、锁定 Yarn 版本的 `packageManager` 字段、`yarn.lock`、`.yarnrc.yml`、Windows 支持矩阵、性能基线、风险结论。最小验证工程已开始实现，支持矩阵和完整基线仍待验证，不能视为整个 M0 已完成。

验证事项：Electron/Vue/Vite 构建；ssh2 真实 PTY；node-pty 的 PowerShell/CMD/WSL；中文 IME；tmux/vim resize；WebGL context 丢失；原生模块打包；系统凭据加密；鸿蒙黄金向量；SSH Agent；3 跳连接；跨窗口状态恢复。

包管理验收：按记录的 Node/Yarn 版本在干净 Windows 环境执行 `yarn install --immutable`，再运行 `yarn typecheck`、`yarn test` 和 `yarn build`；安装及构建不得改写 `yarn.lock`，仓库不得存在其他包管理器的依赖锁文件。Electron 原生模块重建与安装包验证也须纳入 Yarn 脚本流程。

完成条件：每项有可重现记录，失败有已验证的替代或明确降级。跨窗口无损迁移未通过时使用“新建会话”语义，不阻止其他首版模块但必须更新产品文案。

### M1 设计系统与本地基础

依赖 M0 构建与安全桥验证。交付：Vue 应用壳、class 检查、SCSS tokens、主机/身份编辑、本地数据库、凭据保存、PowerShell/CMD/WSL 真实会话。

完成条件：所有自有 DOM 命名可定位；账号未登录也可使用；本地进程关闭无孤儿；应用重启后配置和所选凭据可恢复。

### M2 SSH 与终端工作台

依赖 M1 数据与凭据。交付：SSH 认证、指纹、跳板、标签/分屏、输出搜索、输入/粘贴、tmux、重连、工作区保存、多窗口。

完成条件：目标 Linux/TUI 矩阵核心组合通过；断网不重放命令；关视图不误杀仍被隧道使用的连接；焦点、字体和尺寸稳定。

### M3 SFTP、监控与端口穿透

依赖 M2 会话通道与租约。交付：双栏文件、队列/续传、CPU/内存/网络/磁盘指标、进程列表、L/R/D 与反向穿透中心。

完成条件：真实传输和监控不污染 shell，不明显拖慢输入；隧道监听与公网可达性状态准确；任务取消、失败恢复、权限限制可控。

### M4 账号与同步兼容

依赖 M1 身份/凭据与 M0 密码学互操作。交付：注册登录、记住账号/保持登录、设备管理、Vault、三方合并、离线 outbox、范围显示、敏感轮换与历史恢复。

完成条件：基础配置双向多轮往返无丢失；账号隔离；损坏/未知文档不能清空本地；私钥与主机归属限制真实可见，不误承诺已经升级鸿蒙。

### M5 视觉与 3D 完整打磨

依赖 M2/M3 真实业务状态；基础主题从 M1 开始，不把整体 UI 留到最后。交付：原创 3D 开屏/连接场景、完整/轻量/关闭档、所有空/错/加载态、DPI 与无障碍修整。

完成条件：动效不阻塞输入，没有假进度；关闭/失效后 GPU 与定时器释放；主题和 class 规范全覆盖。

### M6 稳定性与发布

依赖 M1–M5。交付：真实安装包、签名/更新流程、许可证、迁移备份、用户指南、脱敏诊断、最终验收报告。

完成条件：稳定性、安全、性能、兼容与安装门槛通过；阻断级缺陷为零；发布记录列出已知限制。未通过的用户必需功能不能以静态演示或隐藏入口替代。

本阶段计划不预设未经团队容量评估的日历工期。排期应以 M0 测量、跨端依赖和人员可用性重新估算。

## 3. 自动化检查层次

纯逻辑单测：PaneTree、连接状态机、重试退避、类名 token、转发规则校验、路径规范化、队列、监控解析、合并与 crypto fixtures。

组件测试：表单草稿保留、字段错误、快捷键冲突、命名覆盖、状态文案和范围提示。禁止只测实现细节而不验证用户可观察结果。

协议集成：受控真实 sshd、多个认证配置、多个跳板、受限账户、SFTP、GatewayPorts 组合、测试同步服务。单测 mock 不能代替真实协议验证。

桌面 E2E：Playwright Electron 覆盖启动、主机编辑、身份保存、连接、分屏、传输、监控、隧道、同步、锁定、关闭与更新提示。首次运行和凭据测试使用专用测试账号与随机 fixture，不访问用户真实服务器。

性能与视觉：真实 GPU/Windows 机器记录，不仅依赖截图；截图用于层次、裁切、对齐和主题回归。开屏测试至少覆盖开启、关闭、跳过、启动慢、GPU 不可用五种情况。

## 4. 终端兼容矩阵

### 4.1 操作系统与服务器

- 发布基线：Windows 11 x64，1080p/1440p，100%/125%/150%/200% 缩放，至少一个混合 DPI 双屏场景。
- Windows 10 22H2：在依赖支持与组织系统支持策略允许时进行兼容测试；不因程序能启动就承诺长期系统支持。
- Linux 核心组合：Ubuntu 22.04/24.04、Debian 12/13、Rocky/AlmaLinux 9、受支持 Fedora、openSUSE Leap、Alpine 3.x。锁定镜像 tag/digest 后测试，不能使用浮动 latest 作为最终报告。
- SSH：OpenSSH 常见版本矩阵，IPv4/IPv6、密码/Ed25519/RSA/MFA，SFTP-only/禁止 exec/禁止转发账户。
- 本地：Windows PowerShell 5.1、受支持的 PowerShell 7、CMD、WSL2 Ubuntu/Debian；WSL 未安装/发行版停止亦覆盖。

### 4.2 TUI 与输入

按选定 Linux 发行版测试 bash/zsh/fish/sh 和 tmux 3.2/3.4/3.5 系列中的可用版本；再覆盖 M0 调研时的当前稳定 tmux。旧版仅作为兼容样例，不承诺全部历史版本。

必要场景：vim/neovim/nano 编辑中文、less 分页与退出、top/htop 刷新、tmux 多窗格与嵌套、screen、鼠标上报、256 色/真彩、Unicode 框线、emoji/组合字符、IME 候选、长命令折行、全屏程序退出恢复原屏。

验证断线后重连、tmux detach/attach、多次 resize、切字体、切标签、拖到另一显示器、隐藏后恢复。外层 TERM 与 tmux 内层 TERM 单独采集，报告中保留诊断上下文。

## 5. 关键功能验收用例

### A01 凭据与用户

保存用户名但不保存密码，重启后应预填用户名并询问密码；保存密码后可通过保险库认证；共享身份修改影响新连接而不改已有 shell。删除被引用密钥先显示影响范围。应用退出登录不擅自删除本地 SSH 配置。

使用带特殊字符/空格/中文的用户名、路径和口令；检查日志、数据库、WAL、base/outbox、导出包、错误截图与 renderer 持久化存储不存在测试明文秘密。此检查不宣称运行时内存零明文。

### A02 终端完整性

输出确定性的 5 MiB 混合文本以及连续 10 分钟高速输出，核对传输序号/字节与解析前流，不静默丢失或重排。终端显示另用已知控制序列和屏幕快照验证，不能用字节计数替代显示正确性。

UTF-8 字符与 escape sequence 切在任意数据块边界仍正确。8 个会话、4 个可见终端中，另有大文件传输和监控时，输入仍可交互，Ctrl+C 可中断前台程序。

### A03 本地进程

启动四种 Shell、Ctrl+C、交互输入、resize、退出码、中文 cwd；关闭标签只结束所属进程树。强制结束 Local PTY Host 后 UI 显示故障且其他 SSH 可用。系统没有 WSL 时能正常使用其他功能。

### A04 SFTP

1 GiB 文件上传下载后校验 hash；10,000 个小文件目录分批枚举并可取消；测试断网、暂停、恢复、目标变化、磁盘满、只读权限、软链接、同名覆盖和 Windows 保留文件名。

取消/失败不会留下被误认为完整成功的目标文件；队列重启后恢复前重新核对源/目标元数据。

### A05 监控

使用固定 `/proc` fixture 验证 CPU 差分、guest 不重复计数、内存 available、网卡 reset/新增、无 swap、时间间隔与单位；再与受控服务器实测对照，允许采样窗口差异但必须解释。

禁 exec、缺 sh/ps/df、BusyBox、hidepid、容器 cgroup、低权限、时钟变化和网络超时均有明确质量状态。相同主机多窗格只创建预期数量采集器；退出最后订阅者后清理资源。

### A06 隧道与公网穿透

L/R/D 每种测试 IPv4/IPv6/域名、双向数据、背压、half-close、取消、端口占用、断网重连和多客户端连接；SOCKS5 不支持命令返回明确错误。

R 转发分别在 GatewayPorts 限制/允许、防火墙放通/阻断环境测试。用独立外部探测点确认公网可达才标“已验证”；未提供外部探测点时标“远端监听已建立，外部可达未验证”。

3 跳连接测试每跳拒绝、MFA、指纹变化、环路与取消后的资源清理。关闭终端标签仍运行的隧道必须在界面可管理。

### A07 同步与迁移

覆盖 Windows→鸿蒙→Windows 往返，空云库、首次合并、双端离线修改、删除冲突、重复请求、token 并发刷新、401/409/428/429/5xx、损坏密文、超大文档、未知 schema、旧 keyVersion、轮换中断和账号切换。

使用超过 Number.MAX_SAFE_INTEGER 的 revision fixture 验证字符串精度。确认本地 groupId/布局/主题不被下行覆盖。现有私钥缺口场景必须阻止错误的“完整互通”声明。

### A08 视觉、class 与资源释放

静态与动态 DOM 检查全部页面；多窗格、多弹层、v-for 重排后语义类正确且实例类唯一。第三方例外在报告单列。开屏结束、连接结束、关闭监控与图表后没有孤立 rAF、事件监听、计时器和 GPU 场景。

## 6. 性能预算与测量方法

以下是工程目标，不是现有实测成绩。参考机器：至少 4 个现代 CPU 核心、16 GiB RAM、SSD、Windows 11、1080p 60Hz；报告必须记录具体型号、电源模式、依赖版本与显卡。

- 冷启动至工作台可操作：目标 p95 ≤3 秒；本地已有配置的热启动目标 p95 ≤1.5 秒。网络登录/服务器响应时间单独记录。
- 动画：60Hz 设备目标接近 60fps；重负载时允许自动降为轻量档。输入期间不出现持续卡顿或超过 100ms 的频繁主线程长任务。
- 输入：回环测试额外软件延迟目标 p95 ≤30ms，远端总时延另含 RTT，不将网络延迟归为客户端承诺。
- 空闲 CPU：全应用进程树目标 <2% 单逻辑核等效占用（100% 表示占满一个逻辑核），关闭监控和动画后测 60 秒。
- 内存：空工作台全进程 Private Bytes 初始预算 ≤500 MiB；8 会话、4 可见终端、每会话默认 10,000 行回滚目标 ≤1.2 GiB。字体/字符内容影响须记录；超预算需解释与优化，不能只看主进程。
- 稳定性：8 小时混合会话/监控/传输，重复连接与关闭 100 轮；预热后资源不随轮次持续增长。回收延迟与缓存平台期需要单独观察。
- 监控：后台降频可观察，不重复叠加采集；采集进程资源开销在受控远端记录，不能以“无 Agent”声称零开销。

M0 可根据证据调整预算，但必须记录调整原因，不能在验收失败后静默改门槛。

## 7. 主要风险与处理

- R01 鸿蒙同步缺口：保持 v1 基础兼容；主机归属/私钥完整互通作为跨端专项，不混进 Windows 单端承诺。
- R02 ConPTY/native 打包：M0 先跑真实安装包；ABI 与 CPU 架构锁定，不能只在开发环境通过。
- R03 中文/tmux：终端矩阵提前执行；不能等界面完成后再处理输入与字符宽度。
- R04 3D 与终端争用 GPU：单品牌场景、可见终端渲染预算、减少动态效果和 context-loss 降级。
- R05 公网穿透环境限制：向导诊断与独立可达性验证，明确中继与服务端要求。
- R06 监控命令差异：只读能力探测、GNU/BusyBox 双路径、指标级降级、不自动提权。
- R07 多窗口状态丢失：无损迁移必须过真实 TUI 测试；不通过时保留显式新建会话方案。
- R08 账号/身份/凭据混淆：命名、开关和 UI 分离；所有跨账号读写经过 namespace 验证。

## 8. 完成交付检查

文档层面：需求可追踪、术语统一、链接可用、首版与后续明确、现有能力与规划不混淆。应用层面：无 stub/硬编码样例路径/假指标；核心流程有真实后端；状态失败可恢复；没有未经处理的秘密泄露、连接误断或文件丢失问题。

最终验收报告逐项填写通过/失败/受限及证据路径。源项目没有运行过的能力、未测试的系统版本和未验证的性能不得写成已通过。
