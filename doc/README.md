## 1. 已确定的方向

- 技术栈：Electron + Vue 3 + TypeScript + Vite（electron-vite）+ SCSS + xterm.js。
- 包管理：统一使用 Yarn 管理依赖和运行项目脚本；提交 `yarn.lock`，具体版本与安装、构建约定见[技术架构与开发设计](04-TECHNICAL-DESIGN.md#11-yarn-包管理约定)。
- Windows 优先，Windows 11 x64 为首发基线；Windows 10 22H2 为条件兼容目标，开发锁版时核对 Electron、node-pty 与系统支持范围；ARM64 后续验证。
- 深色精致科技感：石墨黑、少量紫青高光、清晰文字、细腻动效；含 3D 开屏和连接反馈。
- SSH 与本地 PowerShell、CMD、WSL 在同一工作台使用；多标签、可调整分屏、多窗口。
- 保存 SSH 用户身份、密码、私钥和口令；保存应用登录状态；各类保存与同步开关分别控制。
- 提供远端 Linux CPU、内存、磁盘、网络等实时指标，以及 SFTP、端口转发与 SSH 反向穿透。
- 兼容鸿蒙项目现有加密同步协议，优先互通主机基础信息、分组对象和转发配置。
- 自有 DOM 元素遵守 `container_页面名_功能名_位置名_扩展名` 命名，重复实例增加唯一实例类。
- 已使用 Yarn 初始化工程并开始 M0/M1；可运行范围、测试结果与未完事项见[开发记录](07-IMPLEMENTATION-STATUS.md)。未修改鸿蒙项目或同步服务端，测试仅使用隔离数据与本机测试 SSH 服务。

## 3. 范围定义

「首版」指完成 M1–M5 并通过 M6 发布验收的完整 Windows v1.0，不是仅能连接的演示版本。核心范围包含本地终端、SSH、SFTP、监控、L/R/D 转发、账号与凭据保存、兼容同步、主题与 3D 动效。

后续增强：原生 ARM64、远程文本编辑器、Zmodem、硬件密钥、串口、Mosh、RDP、插件市场、团队协作、frp 管理等。它们不作为本次首版交付条件。

## 4. 必须公开的兼容边界

1. **分组对象不等于主机归属关系。** 鸿蒙当前 wire schema 没有主机 `groupId`，因此兼容模式能同步分组名称，但主机归组暂为设备本地。完整归组互通需要协议和两端协同升级，单改 Windows 不可实现。
2. **本地保存私钥是首版必需；鸿蒙私钥双向同步不是现成能力。** 鸿蒙目前存在私钥上行与下行缺口，不能让设置页显示“已同步”来掩盖未落地能力。
3. **恢复布局不等于恢复运行中的进程。** SSH 重连是新通道；保留远端程序现场需要 tmux 等远端机制。本地 Shell 在应用彻底退出后也不能凭布局文件复活。
4. **SSH 反向穿透需要可达中继与服务端许可。** 客户端不自带公网 IP，不自动修改服务器防火墙或 `sshd_config`。
5. **3D 是用户体验的一部分，有明确预算。** 它不得延迟已就绪的终端输入；不能靠假进度、假监控数值营造效果。

## 5. 本轮采用的默认解释

- 「保存用户」覆盖 SSH 身份模板、主机默认用户名、应用账号标识与登录会话；不新增服务器操作系统用户管理功能。
- 「远程同步」指配置及用户选择的加密凭据同步；不表示镜像终端进程、日志、监控历史或文件目录。
- 「端口穿透」首版采用 SSH 远程转发到用户自有可达主机，同时提供本地转发和 SOCKS5；商业中继与 frp 接入另列增强。
- 账号不作为本地功能的使用门槛。生产同步仅使用 HTTPS；服务地址通过配置提供，不复制鸿蒙项目中的历史裸 IP。
- 3D 采用原创抽象轨道／连接核心设计，借鉴鸿蒙星航员的阶段反馈，不复制其他产品标识和素材。

这些默认解释使文档可直接用于后续拆任务；若产品范围调整，应同时更新关联功能、协议、UI 和验收项。
